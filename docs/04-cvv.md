# 04. カード検証値: CVK と CVV / iCVV / CVV2

## 登場する鍵

| 鍵 | 役割 |
|---|---|
| CVK A / CVK B (Card Verification Key) | CVV を計算する単一 DES 鍵のペア。2 本で 16 バイト、実質 2-key 3DES 鍵と同じ長さだが、アルゴリズム上は別々の鍵として使う。 |

Mastercard の CVC (Card Validation Code)、JCB の CAV、Amex の CSC も同系統の仕組み。

## CVV の計算

```
入力 = PAN + 有効期限(YYMM) + サービスコード(3 桁) を、右に 0 を詰めて 32 桁(16 バイト)にする
B1, B2 = 先頭 8 バイト, 後ろ 8 バイト

T = DES_CVKA( B1 )
T = DES_CVKA( T XOR B2 )
T = DES_CVKB^-1( T )        (CVK B で復号)
T = DES_CVKA( T )
CVV = decimalize( T ) の先頭 3 桁
```

decimalize は PVV と同じ手順(0-9 を先に拾い、次に A-F を 0-5 として拾う)。

## CVV の種類

計算方法は同じで、入力のサービスコードや置き場所が違う。

| 名前 | 置き場所 | 入力の違い |
|---|---|---|
| CVV (CVV1) | 磁気ストライプのトラック 1 / 2 | 実際のサービスコード(例 `201`) |
| iCVV | IC チップ内のトラック 2 相当データ | サービスコードを `999` に置き換える。磁気ストライプとチップで値が異なるため、チップから読んだデータで磁気ストライプを偽造できない。 |
| CVV2 | カード裏面の印字 | サービスコードを `000` にする等、入力の構成が異なる。ストライプにもチップにも入っておらず、カード現物を持っている証明に使う。 |
| dCVV | 非接触取引ごとに生成 | ATC を入力に含め、取引ごとに値が変わる。 |

本リポジトリの実装はサービスコードを引数で受けるので、`201` で CVV、`999` で iCVV を計算している。

## 実装

- `js/src/cvv.js`、`go/cvv.go`
- Node(OpenSSL 3)は単一 DES の `des-ecb` を既定で提供しないため、JS 版では「K1 = K2 の 3DES は単一 DES と等しい」ことを利用して単一 DES を計算している(`js/src/tdes.js`)。
